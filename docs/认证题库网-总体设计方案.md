# 认证题库网 · 总体设计方案

> 版本：v1.0 ｜ 技术栈：Flask 3 + Jinja2 + 原生 JS（用户端）／纯静态 SPA（管理端）＋ MySQL 8 / SQLite 双后端
> 定位：面向阿里云、华为、AWS、思科认证考生的「认证介绍 + 题库浏览 + 每日刷题 + 积分排名 + 个人荣誉」一站式备考站。

---

## 一、产品定位与信息架构

### 1.1 一句话定位

**认证题库网（CertBank）**：把「考什么、怎么考、刷什么题、练到什么水平」四件事串成一条闭环的认证备考站。

### 1.2 站点地图（Sitemap）

```
认证题库网 /
├── 首页                         GET /                                   （左：认证分类入口；右：排行榜）
├── 厂商频道                     GET /cert/<vendor>
│   ├── 阿里云认证                GET /cert/aliyun
│   ├── 华为认证                  GET /cert/huawei
│   ├── AWS 认证                  GET /cert/aws
│   └── 思科认证                  GET /cert/cisco
│       └── 方向页                GET /cert/<vendor>/<direction>
│           └── 认证详情页        GET /cert/<vendor>/<direction>/<level>
├── 每日答题                     GET /daily-quiz                          （三级联动 → 随机 10 题 → 判分复盘）
├── 排行榜                       GET /ranking?period=day|week|month（入口在个人中心，不占全站导航）
├── 个人中心                     GET /profile                             （登录后可见；/honors 301 到此）
├── 登录 / 注册                  GET|POST /login、/register（图形验证码 / 用户名三层唯一性）
├── 错题本（存量能力）            GET /wrong
├── 管理端（独立入口）            GET /admin/login → /admin/dashboard
└── SEO 辅助                     GET /robots.txt、/sitemap.xml
```

> 登录验证码、用户名唯一性、失败锁定与 Redis 结构的详细设计见
> `docs/登录验证码与用户名唯一性-设计方案.md`。

## 二、页面结构设计

### 2.1 首页 `/`

| 区域 | 内容 | 说明 |
|---|---|---|
| 顶部导航 | 品牌「认证题库网」+ 首页 / 每日答题 + 4 个厂商三级下拉，右上角用户名即个人中心入口；排行榜、错题本不做全站导航项，入口收在个人中心 | 未登录可浏览，答题动作才拦截 |
| Hero | 主标题 + 副标题 + 「开始每日答题」「查看排行榜」双 CTA + 三个数据指标（认证方向数 / 题库总量 / 累计答题） | 首屏直接传达「认证 + 题库 + 排名」 |
| 左栏（主） | 认证分类入口：4 张厂商卡，卡内按方向列出三级认证快捷入口，标注题量 | 支撑「左侧认证分类入口」 |
| 右栏（侧） | 排行榜模块：日 / 周 / 月 Tab，Top 8（排名、昵称、积分、答题次数、最高分）+ 「查看完整榜单」 | 支撑「右侧排行榜」 |
| 底部 | 三步说明（选认证 → 刷 10 题 → 上榜）+ 页脚 | — |

### 2.2 厂商 / 方向页 `/cert/<vendor>`、`/cert/<vendor>/<direction>`

- 面包屑：首页 › 厂商 ›（方向）
- 频道头：厂商介绍、认证等级说明、方向卡片网格（含题量与「进入题库」）
- 右侧：该厂商/方向的榜单 Top 5（复用排行榜组件）
- SEO：独立 title / keywords / description

### 2.3 认证详情页 `/cert/<vendor>/<direction>/<level>`

| 顺序 | 模块 | 内容 |
|---|---|---|
| 1 | 面包屑 + H1 | H1 采用 SEO 标题，如「阿里云ACP云计算高级工程师题库」 |
| 2 | 认证介绍卡（首屏） | 认证定位、适合人群、考试方向、难度（可视化等级）、备考建议 五段式；管理员可后台编辑 |
| 3 | 数据条 | 题库题量、考试代码、建议备考时长、已有多少人练过 |
| 4 | 题库列表 | 该分类下的题目列表（题干摘要、题型、难度），支持分页 |
| 5 | CTA | 「开始每日答题」（带 category 参数）/「浏览全部题目」 |
| 6 | 相关认证 | 同方向其它等级 / 同厂商热门认证 |

### 2.4 每日答题 `/daily-quiz`

1. **选择阶段**：三级联动（厂商 → 方向 → 等级），可带 `?category=` 预选；显示该分类题量与最近成绩。
2. **答题阶段**：顶部 sticky 进度条（第 n/10 题、已用时）、题干 + 选项、上一题/下一题、提交。
3. **结果阶段**：得分环（0–100）、正确率、用时、正确题数；逐题回顾（你的答案 / 正确答案 / 解析）；「再来一组」「查看榜单」「个人中心」。

### 2.5 排行榜 `/ranking?period=day|week|month`

- Tab：日榜 / 周榜 / 月榜
- 我的排名卡（未登录引导登录）
- 榜单表：排名、昵称、积分、答题次数、最高分、趋势（最近 7 天积分折线，内联 SVG）
- 说明区：积分规则（每题 10 分，满分 100）

### 2.6 个人中心 `/profile`（登录；原个人荣誉页并入）

> 顶栏不再单列「个人荣誉」，点右上角用户名进入；旧地址 `/honors` 301 到 `/profile`。
>
> 详细原型、DDL 与接口见 `docs/个人中心-设计方案.md`（资料维护 / 修改密码 / 手机邮箱绑定 /
> 邮箱找回密码）。

- 账号卡：用户名首字母头像、加入时间、累计答对题数、覆盖认证方向数
- 我的排名：日 / 周 / 月三个入口，显示名次、积分、答题次数（点击直达对应榜单）
- 数据概览：累计积分、答题次数、最佳成绩、平均正确率、活跃天数
- 荣誉徽章：首次答题、单次满分、累计 500 / 1000 分、连续 3 天答题（由记录推导）
- 最近答题：最近 5 条卡片式展示
- 历史记录表：时间、认证分类、得分、正确题数、用时

### 2.7 管理端 `/admin/login` → `/admin/dashboard`

| 模块 | 能力 |
|---|---|
| 控制台概览 | 用户数、题库量、今日答题、平均分 |
| 题库管理 | 按认证分类筛选、关键词搜索、单题新增/编辑/删除、批量导入 |
| 题库导入 | 上传 Markdown / JSON，**必须选择三级认证分类**，导入后立即在该栏目可见 |
| 认证介绍管理 | 按厂商/分类搜索，编辑五段式介绍与 SEO 三元组 |
| 分类管理 | 查看 34 个分类、题量、上下架状态、排序、SEO 字段 |
| 用户与权限 | 用户列表、管理员列表 |
| 排行榜数据 | 按日/周/月查看积分汇总 |

## 三、数据库设计

> 共 8 张核心表 + 4 张存量兼容表（daily_sets / daily_records / wrong_questions / points_ledger）。
> 字符集 utf8mb4；MySQL 使用 InnoDB；所有时间字段统一 `DATETIME`/`TEXT`（SQLite 兼容 ISO 字符串）。

### 3.1 ER 关系

```
users 1 ──< quiz_records >── 1 cert_categories 1 ── 1 cert_intros
  │                │                    │
  │                └──< user_honors >───┘
  └──< rankings（按 period_type + period_key 聚合）

cert_categories 1 ──< questions（cert_category_id）
daily_sets 1 ──< questions（daily_set_id，存量按日期答题保留）
```

### 3.3 存量表处理

- `daily_sets / daily_records / wrong_questions / points_ledger` 保留，历史按日期答题、错题本与旧榜单继续可用。
- `questions.daily_set_id` 改为可空：新题库题目只挂 `cert_category_id`，老题目保留 `daily_set_id`。
- 旧 `cert_intro`（单字段 intro）保留只读，启动时按 slug 迁移到 `cert_intros`，随后新页面只读新表。
- 旧 `admin` 表保留，启动时把账号复制进 `admins`，之后所有登录/鉴权只读写 `admins`。

## 四、API 设计

统一前缀：用户端 `/api/*`，管理端 `/api/admin/*`。
响应约定：成功 `{"ok": true, "data": …}`；失败 `{"ok": false, "error": "…"}` + 4xx/5xx。
鉴权：用户端写操作要求 `user_id` session（401 JSON）；管理端全部要求 `admin_id`（401 JSON，不跳 HTML）。

### 4.1 用户端

| 方法 | 路径 | 鉴权 | 说明 |
|---|---|---|---|
| GET | `/api/cert/tree` | 公开 | 完整厂商→方向→认证树（含题量、URL） |
| GET | `/api/cert/<path:path_slug>/intro` | 公开 | 某认证的五段式介绍 |
| POST | `/api/quiz/start` | 登录 | 入参 `{category_id}`；返回 10 题（不含答案）+ 开始时间 |
| POST | `/api/quiz/submit` | 登录 | 入参 `{category_id, question_ids, answers, duration, started_at}`；返回得分/正确率/逐题解析 |
| GET | `/api/ranking?period=day\|week\|month&limit=20` | 公开 | 榜单 + 我的排名 + 近 7 日趋势 |
| GET | `/api/profile/me` | 登录 | 累计积分、最佳成绩、徽章、日/周/月排名、历史记录（`/api/honors/me` 兼容保留） |

**`POST /api/quiz/start` 响应示例**

```json
{"ok": true, "data": {
  "category": {"id": 7, "cert_name": "华为HCIP-数通", "path": "huawei/datacom/hcip"},
  "started_at": "2026-11-06T23:40:12",
  "duration_limit": 900,
  "questions": [
    {"id": 1024, "type": "single", "question": "…", "options": {"A": "…", "B": "…"}, "difficulty": "中"}
  ]
}}
```

**`POST /api/quiz/submit` 响应示例**

```json
{"ok": true, "data": {
  "score": 80, "correct": 8, "total": 10, "accuracy": 0.8, "duration": 312,
  "record_id": 88,
  "review": [
    {"id": 1024, "question": "…", "your_answer": ["A"], "correct_answer": ["B"],
     "is_correct": false, "explanation": "…"}
  ]
}}
```

## 五、SEO 设计

### 5.1 Title 规则

| 页面 | 模板 |
|---|---|
| 首页 | `认证题库网 - 阿里云、华为、AWS、思科认证题库与每日刷题` |
| 厂商页 | `<厂商>认证题库 - ACA/ACP/ACE 题库与每日刷题 - 认证题库网` |
| 方向页 | `<厂商><方向>题库 - HCIA/HCIP/HCIE 认证刷题 - 认证题库网` |
| 认证页 | `<认证名>题库 - 考试大纲、真题练习与每日刷题 - 认证题库网` |

示例：`阿里云ACP云计算高级工程师题库 - 认证题库网`、`华为HCIP数通题库 - 认证题库网`、`AWS Solutions Architect题库 - 认证题库网`、`思科CCNA题库 - 认证题库网`。

### 5.2 Meta 策略

- 每个认证页独立 `keywords`：`<认证名>题库,<认证名>真题,<方向>刷题,<厂商>认证`。
- `description` 取认证介绍 `summary` 前 110 字，附「共 N 道题，支持每日 10 题随机练习」。
- `<link rel="canonical">`、`og:url`、`og:image` 统一由 `seo.py` 输出**绝对地址**，
  域名取 `SITE_BASE_URL`；`og:type/og:locale/twitter:card` 同步。
- 结构化数据：首页 `Organization + WebSite`，频道页 `BreadcrumbList + CollectionPage`，
  认证页 `BreadcrumbList + LearningResource`，排行榜 `WebPage`。
- `/sitemap.xml` 动态输出首页 + 4 厂商 + 方向 + 34 认证页（带 `lastmod`）；
  `/robots.txt` 放行公开页，禁止 `/admin`、`/api/`、`/profile`、`/quiz/`、`/wrong` 等私有路径。

## 八、权限与安全

- 普通用户与管理员**两套 session、两张表**，互不识别；`/admin/*` 不渲染任何用户导航。
- 所有管理接口返回 JSON 401，不返回登录页 HTML。
- 抽题接口不返回 `answer` / `explanation`；交卷后才下发解析。
- `next` 回跳仅允许站内相对路径（`_safe_next`），防开放重定向。
- 导入内容做长度与题型白名单校验；`options` 统一 JSON 序列化，渲染时转义。
- 密码 PBKDF2-SHA256；登录失败统一提示，避免账号枚举。
