# 认证题库网 · 自由练习与模拟题库设计方案

> 版本：v1.0（2026-11-07）
> 范围：认证详情页的「模拟题库」区块、`/practice/<slug>` 模拟答题、交卷判分与解析、管理端组卷与考试规则配置
> 原则：严格两层「认证页题库卡片 → 模拟答题」，列表不出现任何题干；题库的题量与题型比例必须与真实考试规则一致才允许发布。

---

## 一、设计目标与边界

### 1.1 与「每日答题」的分工

| 维度 | 每日答题 `/daily-quiz` | 模拟题库（认证页内嵌） |
|------|------------------------|----------------------|
| 入口 | 认证详情页「开始每日答题」 | 同一认证详情页的「模拟题库」区块 |
| 题源 | 全站题池随机抽 10 题 | 管理员组好的固定题库，按整卷作答 |
| 题量 | 固定 10 题 | 由考试规则决定（如 100 题） |
| 计时 | 不计时 | 按规则倒计时，超时服务端自动交卷 |
| 判分 | 每题 10 分 | `正确题数 × 总分 / 总题数`，完全匹配才得分 |
| 结果 | 得分、正确率、逐题解析 | 得分、合格判定、逐题解析、错题筛选、重新练习 |
| 记录 | `quiz_records` + 榜单积分 | `bank_practice_sessions` / `answers` / `progress`，不参与日榜 |

两者共用 `base.html`、按钮与卡片视觉体系；文案上前者叫「每日答题」，后者按题库类型叫「专项训练 / 全真模拟」。

### 1.2 非目标

- 不做逐题即时对错：未交卷前不下发答案与解析，避免背题。
- 不做跨设备断点续答之外的实时同步（同一账号以服务端保存的作答为准）。
- 不把模拟练习计入排行榜积分，避免与每日答题的积分口径混淆。
- 不设独立题库目录页：题库属于某个认证，离开认证页单独罗列反而增加一次选择。

## 二、信息架构与 URL

```
/cert/<vendor>/<direction>/<level>   认证详情页：五段式介绍 + 「模拟题库」区块
└── /practice/<slug>                 模拟答题（四态：加载 / 未登录 / 出错 / 答题）
    └── 交卷后同一页面切换为成绩与逐题解析
```

| 路由 | 方法 | 说明 | 登录 | SEO |
|------|------|------|------|-----|
| `/cert/<path>` | GET | 认证详情，含该认证下已发布的题库卡片 | 否 | 可索引，进 sitemap |
| `/practice` | GET | 旧独立目录页，**301 → `/`**（只保留兼容） | — | 不进 sitemap |
| `/practice/<slug>` | GET | 模拟答题页，`slug` 为题库标识 | 否（答题接口需登录） | `noindex,follow` |
| `/api/practice/*` | * | 见第六节 | 部分 | `X-Robots-Tag: noindex` |

题库归属于认证：`question_banks.cert_path` 与认证页路径一一对应，管理员发布后立刻出现在该页，
其他认证页不会出现。全站导航不再单列「自由练习」入口。

**区块职责**

| 区块 | 内容 | 数据来源 |
|------|------|----------|
| `leaf-score` | 首屏「N 道题可练」= max(模拟题库总题量, 每日答题题池) | `bank_total` / `summary` |
| `hero-actions` | 「查看模拟题库」锚点到 `#bank-list`；无题库时隐藏 | `banks` |
| `#bank-list` | 标题 + 汇总「共 N 套 · M 道题」+ 题库卡片 | `list_banks(cert_path=path)` |
| `bank-grid-cert` | 单列布局（认证页主栏较窄，题库通常 1-3 套） | `static/practice.css` |
| 空态 `empty-box` | 「暂时还没有模拟题库」+ 管理员去后台 / 游客去做每日答题 | 静态文案 |
| `bank-card` | 见 3.2 | `_bank_payload()` |

**约束**

- 只展示 `status='published'` 的题库；停用后立即从前端消失，历史成绩仍在。
- 按 `cert_path` 精确过滤，不按厂商或方向兜底，避免「ACP 大模型页出现云计算卷」。
- 卡片不做整卡跳转（只有题库名与按钮是链接），避免误点；也不再平铺任何题干与选项。
- 不加筛选 tab：单个认证下的题库通常 1-3 套，筛选成本高于收益；状态用卡片内的进度与色点表达。

### 3.2 题库卡片字段

| 字段 | 示例 | 来源 | 规则 |
|------|------|------|------|
| 分类标签 | `基础` / `进阶` / `冲刺` / `错题本` | `question_banks.level_tag` | 四选一，颜色区分 |
| 试卷类型 | `全真模拟` / `专项训练` | `rule_code != custom` | 关联预置规则即全真模拟 |
| 难度 | `简单` / `中等` / `困难` | `question_banks.difficulty` | 右上角弱化展示 |
| 题库名称 | `ECS 弹性计算专项题库` | `question_banks.name` | 可换行，最多 2 行 |
| 简介 | `聚焦 ECS 实例、云盘、快照……` | `description` | ≤300 字，列表截断 2 行 |
| 题量 | `共 30 题` | 实际启用题目数 | 不含已停用题目 |
| 题型比例 | `20 单选 · 10 多选` | 实际题目统计 | 与声明值不一致时无法发布 |
| 规则摘要 | `45 分钟 · 24 分合格` | 规则快照 | 满分、合格线、时长 |
| 练习状态 | `尚未开始` / `已练 30/30` | `bank_practice_progress` | 已练题数 / 总题数 |
| 错题提示 | `错题 1` | `progress.wrong_count` | 红色圆点，仅 >0 时显示 |
| 进度条 | `███████` | `answered_count / question_count` | 未开始时隐藏 |
| 主按钮 | `开始练习` / `继续练习` | `progress.started` | 有未交卷场次时跳回原场次 |
| 更新时间 | `更新于 2026-11-07` | `updated_at` | 日期粒度 |

**交互规则**

1. **进入即开考**：`boot()` 先尝试 URL 上的 `?session=` 恢复；失效则 `POST /banks/<slug>/start`，有进行中场次直接续答，否则新建并随机打乱题目顺序。
2. **顶部标识**：题库名、`当前题库：X | 第 N/M 题`、倒计时、完成进度条、题型/分数/时长摘要。
3. **逐题保存**：单选点击即选中，多选点「下一题」或切题时保存；前端 320ms 防抖 + Promise 串行，避免并发覆盖。保存成功显示「已保存 HH:MM:SS」。
4. **倒计时**：以服务端 `remaining_seconds` 为准，本地每秒递减；≤5 分钟变红；归零自动 `POST submit {reason:"timeout"}`。
5. **交卷确认**：弹层提示未作答题数，确认后按钮置灰防重复提交。
6. **刷新恢复**：`?session=<token>` 保留场次；刷新后回到上次题目与已保存答案。
7. **成绩页**：隐藏答题页头部与答题区，只显示成绩卡 + 逐题解析，避免「已交卷还在倒计时」的误解。

└──────────────────────────────────────────────────────────────────────────────┘

- 得分环：≥ 合格分为绿色 `is-pass`，否则红色 `is-fail`，同时给出「合格 / 未合格」徽章。
- 统计项：正确题数、正确率、用时（`mm:ss` 或 `hh:mm:ss`）、错题数。
- 「查看错题（N）」在「只看错题」与「查看全部（M）」之间切换，空错题时提示「本场没有错题，全部答对」。
- 「重新练习」调用 `start` 且 `restart:true`，新建场次并清空页面上的旧答案；历史成绩保留。
- 超时交卷在成绩卡上方给出说明：「考试时间已到，系统已自动交卷；已作答题目照常判分。」

## 四、考试规则与约束

### 4.1 预置规则（`exam_rules`）

| code | 名称 | 总题量 | 单选 | 多选 | 总分 | 合格分 | 时长 |
|------|------|--------|------|------|------|--------|------|
| `aliyun-acp-cloud` | 阿里云 ACP 云计算高级工程师 | 100 | 70 | 30 | 100 | 80 | 120 分钟 |
| `aliyun-acp-llm` | 阿里云 ACP 大模型高级工程师 | 75 | 50 | 25 | 100 | 80 | 120 分钟 |
| `custom` | 自定义规则 | 自填 | 自填 | 自填 | 自填 | 自填 | 自填 |

> ACP 大模型官方未公开单选/多选的精确拆分，`50 + 25` 为按 2:1 的工程化假设，已在规则描述中注明；管理员可在「考试规则」里改成实际比例。

### 4.2 规则快照

创建题库时把规则的 6 个关键值复制进 `question_banks`（`total_questions / single_count / multiple_count / total_score / pass_score / duration_minutes`），之后：

- 管理员改规则 **不会** 改动已建题库，已发布试卷的题量、分数、时长保持稳定；
- 题库再次编辑保存时，若所选规则已变化，按最新规则重新快照；
- 发布时比对快照与当前规则，不一致则拦截，提示「关联的考试规则已更新，请编辑题库并重新保存以同步最新规则」。

### 4.3 发布校验（`publish_check`）

| 校验项 | 条件 | 失败提示 |
|--------|------|----------|
| 题量声明 | `total_questions > 0` | 题库题量声明为 0，请先配置考试规则 |
| 是否有题 | 实际启用题数 > 0 | 题库内还没有题目，至少需要 N 题 |
| 总题量 | 实际题数 == 声明题数 | 实际题目 X 题，与声明的 Y 题不一致 |
| 单选数 | 实际单选 == 声明单选 | 单选题实际 X 道，与要求的 Y 道不一致 |
| 多选数 | 实际多选 == 声明多选 | 多选题实际 X 道，与要求的 Y 道不一致 |
| 规则存在 | `rule_code` 可查到且启用 | 关联的考试规则已被删除或停用 |
| 规则同步 | 快照 == 当前规则 | 关联的考试规则已更新，请重新保存 |

- 新建题库默认 `draft`，只能保存草稿；校验全部通过才允许 `published`。
- 已发布题库再次发布时跳过校验（`publish_check` 对 `published` 直接返回空数组），改题不会把线上题库突然下架。
- 题库停用（`disabled`）后不再出现在 `/practice` 目录，直达链接只显示「题库已停用」提示且不能开新场次；`bank_practice_sessions / answers / progress` 全部保留，历史成绩与解析仍可查看。

### 4.4 自定义规则校验

- 总题量 1-300；
- `单选 + 多选 == 总题量`；
- `0 <= 及格分 <= 总分`，总分 > 0；
- 时长 1-600 分钟。

## 五、数据库设计

权威 DDL：`schema_mysql.sql`（MySQL 8.0）；`models.SCHEMA` 为等价 SQLite 版本。新增 6 张表，全部通过 `bank_id` / `user_id` 关联，不修改既有表。

```
exam_rules 1 ──── n question_banks 1 ──── n bank_questions
                         │
                         ├──── n bank_practice_sessions 1 ──── n bank_practice_answers
                         └──── n bank_practice_progress
users 1 ──── n bank_practice_sessions / bank_practice_answers / bank_practice_progress
```

## 七、关键算法

### 7.1 判分

```python
submitted = set(user_answer)          # ["A","C"]
correct = set(question.answer)        # ["A","C","D"]
is_correct = bool(submitted) and submitted == correct   # 多选不给部分分
score = round(correct_count * total_score / total, 1)
accuracy = round(correct_count / total * 100, 1)
passed = score >= pass_score
```

- 未作答按错处理；
- 多选少选、多选错选均不得分；
- 得分按比例折算，允许小数（如 25 题满分 30 分，答对 24 题得 28.8 分）。

### 7.2 进度增量更新（`_touch_progress`）

交卷结算时逐题写 `bank_practice_answers`，同时按「该题最后一次作答」维护 `bank_practice_progress`：

| 上次 | 本次 | `answered_count` | `correct_count` | `wrong_count` |
|------|------|------------------|-----------------|---------------|
| 未答 | 答对 | +1 | +1 | 0 |
| 未答 | 答错 | +1 | 0 | +1 |
| 答错 | 答对 | 不变 | +1 | -1 |
| 答对 | 答错 | 不变 | -1 | +1 |

这样「错题答对后错题数归零」，列表页的「错题 N」始终是当前仍错的题数，而不是历史累计错误次数。

### 7.3 超时兜底

- 开考写 `deadline_at = started_at + duration_minutes`；
- `finalize_expired(user_id, bank_id)` 在 `start` / `save_answer` / `get_session` 三处调用：查出 `deadline_at < now` 的 `ongoing` 场次，按已保存答案判分，`submit_reason='timeout'`，`duration` 取 `min(实际经过秒数, duration_minutes*60)`；
- 前端倒计时归零也会主动提交一次，服务端结算具备幂等性，重复提交返回同一结果。

### 7.4 场次冻结

`question_ids` 在开考时写入并随机打乱，后续管理员增删题目不影响进行中的试卷；交卷解析按 `question_ids` 顺序输出，题号与作答时一致。

## 八、安全与防泄题

1. **答案不下发**：`_session_payload` 只输出 `id/type/question/options/difficulty`，`answer` / `explanation` 仅在 `status='submitted'` 时由 `_result_payload` 输出。
2. **服务端判分**：前端只上报选项字母，分数、对错、合格判定全部在服务端计算。
3. **越权防护**：所有场次接口按 `user_id + token` 双条件查询，换账号拿到 token 也读不到别人的卷子。
4. **随机 token**：`secrets.token_urlsafe(24)`，不可枚举。
5. **重复提交**：`submit_session` 对已交卷场次直接返回结果，不重复写作答与统计。
6. **发布校验**：题量/题型比例不满足规则时禁止发布，避免前端出现「100 题试卷只有 30 题」的体验事故。
7. **删除保护**：有练习记录的题库禁止物理删除，只能停用，保证历史成绩与解析可回看。

## 九、SEO 与可访问性

- 认证详情页可索引：`BreadcrumbList` + `LearningResource`（含题量、难度、厂商），进 `sitemap.xml`；题库卡片随页面被收录。
- `/practice/<slug>` 为 `noindex,follow`：答题页对搜索引擎无内容价值，且避免题库被批量抓取。
- 题库名与「开始/继续练习」都是真实 `<a>`（`/practice/<slug>`），禁用 JS 仍可进入；卡片本身不做整卡跳转，避免误触。
- 答题页选项使用原生 `input[type=radio/checkbox]` + `label`，读屏可识别；倒计时 `aria-live="polite"`。
- 颜色不是唯一信息载体：状态同时有文字（尚未开始 / 已练 30/30 / 错题 1）与圆点颜色。
