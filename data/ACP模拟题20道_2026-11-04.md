## 一、ECS 云服务器（第 1–3 题）

**1.** 某业务数据库运行在 ESSD PL1 云盘上，业务高峰期 IOPS 不足导致查询延迟升高。运维检查发现该云盘容量为 1 TB，实际使用率不足 30%，业务要求不扩容、不迁移数据、不停机。最合适的处理方式是？

- A. 扩容云盘容量至 2 TB，再重新分区格式化
- B. 将云盘更换为高效云盘，利用其更高的吞吐能力
- C. 将云盘性能级别由 PL1 升级为 PL2（原地变配）
- D. 为该实例追加挂载两块新云盘，不改变原盘配置

**答案：C**

**解析：**
- **考点**：ESSD 云盘的 IOPS/吞吐上限由「容量 × 性能级别（PL0/PL1/PL2/PL3）」共同决定。当容量本身不是瓶颈时，提升性能级别是原地生效的变配操作，无需迁移数据、无需停机（部分场景需在控制台确认变配并在实例内重新识别设备）。
- **易错点**：
  - ① 误以为「ESSD 的 IOPS 只跟容量有关」，于是去扩容——既浪费钱又解决不了性能级别上限的问题；
  - ② 高效云盘、SSD 云盘的 IOPS 上限远低于 ESSD，改用高效云盘是性能降级；
  - ③ 追加挂载多块盘并不会提升单块盘的 IOPS，必须做 RAID0 才能真正叠加，而 RAID0 会牺牲可靠性，且需要重建数据目录，与题干「不迁移数据」冲突。
- **延伸**：PL 级别对应的单盘 IOPS 上限随容量线性增长，规划时应「按峰值 IOPS 反推容量 + PL 组合」，而不是先买容量再看性能。

**2.** 某应用部署在 ECS 上，需要读取同地域 OSS 中的业务文件。安全规范明确禁止在服务器磁盘、环境变量或代码中保存任何长期 AccessKey。最符合规范的做法是？

- A. 为 ECS 实例绑定 RAM 角色并授予 OSS 最小权限，应用通过实例元数据服务获取 STS 临时凭证
- B. 创建一个专用 RAM 用户，把其 AccessKey 写入 `/etc/profile` 供应用读取
- C. 使用主账号 AccessKey，并通过安全组做 IP 白名单限制
- D. 把 AccessKey 加密后存放在自建配置中心，程序启动时解密使用

**答案：A**

**解析：**
- **考点**：ECS 实例 RAM 角色（Instance RAM Role）的本质是让实例以「角色」身份通过元数据服务（`100.100.100.200`）获取 STS 临时凭证，凭证有效期短、由平台自动轮换，代码中无需落地任何长期密钥。
- **易错点**：
  - ① 选项 D 看似安全，但程序仍需要一个凭证去解密配置中心，问题只是被转移而非消除，且密钥仍可能随镜像/配置文件泄露；
  - ② 选项 B 把 AK 落在磁盘上，一旦快照、镜像、日志外泄即等同泄露；
  - ③ 选项 C 用主账号 AK 属于最严重违规，IP 白名单无法防止从同一台机器发起的滥用。
- **延伸**：绑定/更换实例 RAM 角色后部分场景需重启实例方可生效；生产上应遵循最小权限，为角色授予仅限目标 Bucket 前缀的 `oss:GetObject` 等权限。

**3.** 某核心数据库实例挂载了 3 块 ESSD 云盘（分别存放数据文件、在线日志、临时文件）。运维需要定期为这 3 块盘创建「同一时间点」的快照，避免恢复后数据文件与日志时间点错位导致无法正常启动。最合适的做法是？

- A. 按顺序依次为 3 块云盘分别创建快照
- B. 为 3 块云盘绑定同一个自动快照策略，由策略统一触发
- C. 使用 OSS 跨区域复制同步快照到备地域
- D. 使用快照一致性组，一次性为 3 块云盘创建同一时间点的快照

**答案：D**

**解析：**
- **考点**：快照一致性组（Snapshot Consistency Group）用于对同一实例的多块云盘（或多实例的多块盘）在同一时刻发起快照，保证多盘之间的时间点一致，属于「崩溃一致性」。
- **易错点**：
  - ① 逐块创建快照之间存在秒级甚至分钟级偏差，多盘数据可能互相矛盾，恢复后数据库无法正常崩溃恢复；
  - ② 自动快照策略是按盘分别触发的，即使策略相同也不保证严格同一时刻；
  - ③ 跨区域复制解决的是「异地副本」问题，与「多盘时间点一致」无关；
  - ④ 一致性组只保证崩溃一致性，「应用一致性」还需数据库自身配合（如冻结写、flush 日志），二者不可混淆。
- **延伸**：一致性组同样可关联自动快照策略实现周期化；恢复时需整组回滚，不能只挑其中一块盘回滚。

## 二、VPC 专有网络（第 4–6 题）

**4.** 某公司通过 IPsec-VPN 将本地 IDC 与阿里云 VPC 打通。运行数月后发现链路偶发中断，且每次恢复都依赖运维人工介入切换。公司要求在不新增专线成本的前提下提升链路可靠性、实现故障自动切换。最合适的方案是？

- A. 提升 VPN 网关的带宽规格
- B. 在同一条隧道上再增加一条静态路由
- C. 启用双隧道模式（主备或双活隧道），并配置 BGP 动态路由实现自动切换
- D. 为 VPC 内 ECS 绑定 EIP，改为公网直连 IDC

**答案：C**

**解析：**
- **考点**：阿里云 VPN 网关支持双隧道模式，通过两条独立的 IPsec 隧道（走不同的底层链路）提供冗余；配合 BGP 动态路由可在隧道故障时自动撤销路由、切换到备用隧道，实现秒级收敛。
- **易错点**：
  - ① 带宽规格只影响吞吐，与链路可靠性无关；
  - ② 在同一隧道上增加静态路由没有任何冗余意义，静态路由本身也不会感知隧道故障；
  - ③ 公网直连既不可控也不安全，等于放弃 VPN 的价值。
- **延伸**：双隧道需对端设备支持两个公网 IP 或两个隧道端点；若对端只支持单隧道，可用「VPN 网关 + 专线」组合，或使用智能接入网关（SAG）作为备份链路。

**5.** 某 VPC 内的 ECS 均无公网 IP，需要以**内网方式**访问同地域 OSS，且要求：不经过 NAT 网关、不产生公网流量费用，并且只允许该 VPC 访问指定的 Bucket。最合适的组合方案是？

- A. 为 ECS 绑定 EIP，通过 OSS 公网 Endpoint 访问
- B. 创建 OSS 网关终端节点（Gateway Endpoint），并在 Bucket Policy 中限制仅允许该 VPC 访问
- C. 通过 NAT 网关做 SNAT 后访问 OSS 内网 Endpoint
- D. 使用 CDN 回源 OSS，并开启私有 Bucket 回源

**答案：B**

**解析：**
- **考点**：网关终端节点（Gateway Endpoint）是 PrivateLink 体系中的一种，用于从 VPC 私网直接访问 OSS、表格存储等云服务，流量不出 VPC、不占用 NAT 带宽、不产生公网流量费；配合 Bucket Policy 的 `acs:SourceVpc` 条件即可实现「仅本 VPC 可访问」。
- **易错点**：
  - ① 用 NAT 网关访问内网 Endpoint 在链路上虽然能通，但会产生 NAT 网关实例费和流量处理费，且无法限制来源为某个 VPC；
  - ② 绑定 EIP 走公网 Endpoint 会产生公网流量费，且源 IP 是弹性 IP，难以做稳定授权；
  - ③ CDN 回源属于公网链路，不满足「内网访问」要求。
- **延伸**：访问 OSS 的私网路径有三种——同地域内网 Endpoint、网关终端节点、PrivateLink 反向访问；终端节点还需在对应路由表中确认路由已下发。

**6.** 某政务云项目要求业务系统支持 IPv6 访问。运维已在 VPC 和交换机上开通 IPv6 网段，并为 ECS 分配了 IPv6 地址，实例内部 `ifconfig` 也能看到该地址，但公网用户始终无法通过 IPv6 访问业务。最可能缺失的配置是？

- A. 未开通 IPv6 网关，也未为该 IPv6 地址购买公网带宽
- B. 未配置 NAT 网关
- C. 未为 ECS 绑定 EIP
- D. 未创建 SLB 实例

**答案：A**

**解析：**
- **考点**：VPC/交换机的 IPv6 网段只提供私网 IPv6 地址；要让 IPv6 地址具备公网访问能力，必须开通 IPv6 网关并为其购买 IPv6 公网带宽（IPv6 地址默认不具备公网连通性）。
- **易错点**：
  - ① 误以为「交换机开通 IPv6 后实例自动获得公网 IPv6」；
  - ② 试图用 EIP 解决——EIP 是 IPv4 资源，与 IPv6 无关；
  - ③ 误以为 NAT 网关能提供 IPv6 出/入向公网能力（NAT 网关主要解决 IPv4 SNAT/DNAT）。
- **延伸**：IPv6 公网带宽按流量或按带宽计费；安全组同时支持 IPv4/IPv6 规则，开通后需确认安全组已放行对应 IPv6 源地址段。

## 三、SLB 负载均衡与 CDN（第 7–9 题）

**7.** 某微服务系统需要实现：`api.example.com/v1/*` 转发到旧版服务组、`/v2/*` 转发到新版服务组；把 HTTP 请求 301 重定向到 HTTPS；并将携带请求头 `x-canary: true` 的流量单独导入灰度服务组。应选择的产品与配置是？

- A. CLB 四层（TCP）监听
- B. CLB 七层（HTTP/HTTPS）监听
- C. NLB 网络型负载均衡
- D. ALB 应用型负载均衡，使用转发规则组按域名/路径/HTTP 头转发，并配置重定向规则

**答案：D**

**解析：**
- **考点**：ALB 支持基于域名、路径、HTTP 头、Query、Cookie、源 IP 等多维条件的转发规则，并内置重定向、固定响应、加权转发等动作，是七层精细化路由的首选。
- **易错点**：
  - ① CLB 七层只支持基于域名和 URL 的简单转发，**不支持按 HTTP Header 转发**，也无法做规则化的 301 重定向；
  - ② CLB 四层、NLB 工作在传输层，看不到 HTTP 头，天然无法实现；
  - ③ 容易把「灰度」理解为只能在 DNS 层做，其实 ALB 的规则 + 权重即可完成灰度。
- **延伸**：ALB 还支持基于 Cookie 的会话保持、基于 QPS 的限流；多规则间按优先级匹配，需注意规则顺序。

**8.** 某站点源站对静态资源返回 `Cache-Control: max-age=3600`。运维在 CDN 控制台为该 URL 路径单独配置了「缓存过期时间 10 秒」，并关闭了「遵循源站」选项。用户实际命中的缓存过期时间是？

- A. 3600 秒，源站响应头优先级最高
- B. 1800 秒，取 CDN 默认值
- C. 10 秒，CDN 控制台配置优先于源站响应头
- D. 不缓存，直接回源

**答案：C**

**解析：**
- **考点**：CDN 缓存过期时间的优先级为：**CDN 控制台自定义配置 > 源站 Cache-Control/Expires（在「遵循源站」开启时生效）> CDN 默认策略**。关闭「遵循源站」后，源站响应头被忽略，以控制台配置为准。
- **易错点**：
  - ① 想当然认为「源站说了算」，实际 CDN 是代理缓存，配置可覆盖源站语义；
  - ② 忽略「遵循源站」这个开关的作用，导致排查方向错误；
  - ③ 把「不缓存」与「缓存 0 秒」混淆，二者在 CDN 上是不同配置项。
- **延伸**：动态接口应配置「不缓存」或极短过期时间；静态资源配合「忽略参数」可显著提升命中率，但会带来带参 URL 内容错乱的风险。

**9.** 源站 Nginx 上配置了多个虚拟主机，按请求的 Host 头区分站点。加速域名 `static.example.com` 已正确 CNAME 到 CDN，源站地址填的是 `origin.example.com`，但回源请求总是命中源站的默认站点。应优先检查并配置？

- A. 修改 CNAME 记录，直接指向源站 IP
- B. 将 CDN 的「回源 HOST」配置为 `origin.example.com`
- C. 关闭 CDN 缓存，强制每次回源
- D. 开启 Range 回源

**答案：B**

**解析：**
- **考点**：回源 HOST 决定 CDN 节点回源时携带的 Host 头。默认回源 HOST 等于加速域名（此处为 `static.example.com`），源站按 Host 匹配虚拟主机时便会落到默认站点；将其改为源站期望的站点域名即可正确匹配。
- **易错点**：
  - ① 误把「回源 HOST」理解成「源站地址」，二者是两个独立配置项；
  - ② 通过 CNAME 直接指向源站 IP 会绕过 CDN，彻底失去加速与防护；
  - ③ 关闭缓存只改变回源频率，不改变 Host 头，问题依旧。
- **延伸**：回源协议（HTTP/HTTPS）与回源端口同样需要与源站监听保持一致，否则会出现 502/回源超时。

## 四、OSS 对象存储（第 10–12 题）

**10.** 某应用部署在华东 1（杭州）的 ECS 上，代码中使用 `oss-cn-hangzhou.aliyuncs.com` 访问同地域 Bucket。运维发现每月 OSS 账单中「外网流出流量」费用很高，而实际业务量并不大。最直接有效的优化措施是？

- A. 购买 CDN 流量包来抵扣这部分费用
- B. 将 Bucket 存储类型改为低频访问
- C. 开启 OSS 传输加速
- D. 将访问 Endpoint 改为同地域内网 Endpoint `oss-cn-hangzhou-internal.aliyuncs.com`

**答案：D**

**解析：**
- **考点**：OSS 同地域内网 Endpoint 形如 `oss-<region>-internal.aliyuncs.com`，ECS 通过它访问同地域 Bucket 时流量走内网，**不计外网流出流量费**（仍计请求费与存储费）。
- **易错点**：
  - ① 把 `oss-cn-hangzhou.aliyuncs.com` 误认为内网地址，实际上它是公网 Endpoint；
  - ② 认为内网访问「完全免费」——只免流量费，请求次数费照收；
  - ③ 跨地域使用内网 Endpoint 根本不通，必须用公网 Endpoint 或传输加速；
  - ④ 改存储类型只影响存储单价，与流量费无关。
- **延伸**：若 ECS 与 Bucket 不同地域，可考虑传输加速或 CDN 回源；内网 Endpoint 也适用于容器、函数计算等同类同地域场景。

**11.** 某金融机构受监管要求：写入 OSS 的交易凭证在 5 年内**任何人（包括主账号）都不得修改或删除**，到期后方可清理。应采用的配置是？

- A. 开启合规保留策略（WORM），设置 5 年保留期并锁定
- B. 开启版本控制，依靠历史版本防止误删
- C. 配置生命周期规则，5 年后自动转归档存储
- D. 配置跨区域复制，保留异地副本

**答案：A**

**解析：**
- **考点**：合规保留策略（WORM，Write Once Read Many）在保留期内对象不可覆盖、不可删除，且策略锁定后**任何账号（含主账号）都无法提前删除对象，保留期只能延长不能缩短**，是满足金融、医疗等合规留存要求的专用能力。
- **易错点**：
  - ① 版本控制只能防「误删」（删除产生的是删除标记），拥有权限者仍可永久删除指定版本，不满足「谁都删不掉」；
  - ② 生命周期转归档只改变存储类型，对象依旧可被删除；
  - ③ 跨区域复制只是多一份副本，源端删除可同步到目标端。
- **延伸**：策略锁定不可逆，务必先用小范围 Bucket 验证保留天数；WORM 常与「对象锁定 + 版本控制」配合使用。

**12.** 某客户需要将 50 GB 的备份文件上传到 OSS，公网链路不稳定，经常在中途断开，重传一次耗时数小时。最合适的上传方式是？

- A. 简单上传（PutObject）一次性提交
- B. 追加上传（AppendObject）分多次追加
- C. 分片上传（Multipart Upload），记录 uploadId 实现断点续传与并行上传
- D. 表单上传（PostObject）由浏览器直传

**答案：C**

**解析：**
- **考点**：分片上传将大对象切分为多个 Part 并行上传，支持断点续传（记录 uploadId + 已完成 Part 列表，续传时跳过已上传分片），最后调用 CompleteMultipartUpload 合并，是超大文件的标准方案。
- **易错点**：
  - ① 简单上传一旦中断只能整体重传，且大文件更容易失败；
  - ② 追加上传适用于日志类「顺序追加」，不支持并行与断点续传，也不适合备份文件；
  - ③ 忘记 Complete 会导致上传「看起来成功但对象不存在」；未完成的分片会以碎片形式占用存储并计费，需用生命周期规则清理碎片。
- **延伸**：分片大小通常取 5–100 MB（末片可小于 5 MB），Part 数量上限 10000，需据此反算分片大小。

## 五、数据库 RDS / PolarDB / Redis（第 13–15 题）

**13.** 安全审计要求：完整记录 RDS MySQL 上执行过的所有 SQL（含 DDL、DML 与查询）、执行账号、客户端 IP 与执行时间，日志保留 180 天，同时还要能定位慢 SQL 并做趋势分析。最合适的方案是？

- A. 开启慢查询日志，并调低 `long_query_time`
- B. 开启 binlog，并通过 DTS 订阅增量数据自行解析
- C. 仅依赖云监控的数据库性能指标做分析
- D. 开启 SQL 洞察与审计功能，配置日志留存 180 天，并使用其慢 SQL 分析能力

**答案：D**

**解析：**
- **考点**：SQL 洞察（原 SQL 审计）以全量方式记录 SQL 语句、来源 IP、账号、执行耗时与扫描行数，可直接用于合规审计、问题溯源与慢 SQL 分析，并支持按时间范围导出。
- **易错点**：
  - ① 慢日志只记录超过阈值（默认 1 秒）的 SQL，**不满足「全量记录」的审计要求**；
  - ② binlog 只记录数据变更，不含 SELECT，且无法还原客户端 IP；
  - ③ 云监控提供的是 CPU、连接数、IOPS 等指标，不含 SQL 文本。
- **延伸**：SQL 洞察有存储容量与保留期限制，长期留存需定期导出至 OSS 或 SLS；开启审计会带来一定性能开销，需评估业务高峰。

**14.** 某 Redis 实例偶发 1–2 秒卡顿，监控显示主从同步延迟增大，且某一分片内存占用明显高于其他分片。排查发现一个 Hash 类型的 Key 存有约 200 万个 field，且仍在被高频读写。最合理的治理措施是？

- A. 先用 UNLINK 异步删除该 Key 释放空间，同时改造业务按维度拆分为多个 Key（或按 field 分片）
- B. 直接对该 Key 执行 DEL 删除，立即释放内存
- C. 扩容实例规格，提升整体内存与 CPU
- D. 开启 AOF 持久化以提升数据安全性

**答案：A**

**解析：**
- **考点**：这是典型「大 Key」问题。大 Key 会导致：单分片内存倾斜、读写阻塞主线程、主从同步与持久化时产生长耗时、集群无法水平打散。治理原则是**异步删除 + 结构拆分**，从根上消除单 Key 过大。
- **易错点**：
  - ① `DEL` 是同步操作，删除上百万元素的 Key 会长时间阻塞 Redis 单线程，可能直接触发业务超时甚至主从切换，应使用 `UNLINK`；
  - ② 单纯扩容只是把问题推迟，单 Key 仍落在同一分片，倾斜与阻塞依旧；
  - ③ AOF 持久化会因大 Key 重写而放大阻塞，反而加剧问题。
- **延伸**：大 Key 判定通常参考「String 值 > 10 MB、集合元素数 > 5000~10000」；日常可用 DAS、离线 RDB 分析工具定期体检。

**15.** 大促前，某业务需要临时增加 3 个只读节点承接查询流量，要求分钟级完成、对线上无影响；同时希望存储费用按实际使用量计费，而非预先购买固定容量。最符合要求的产品与方案是？

- A. RDS MySQL 只读实例，逐个创建并等待数据复制完成
- B. PolarDB MySQL 版，利用存储计算分离架构秒级/分钟级增加只读节点，存储按实际使用量计费
- C. 在 ECS 上自建 MySQL 主从，手工搭建 3 个从库
- D. 使用 Redis 读写分离承接查询

**答案：B**

**解析：**
- **考点**：PolarDB 采用计算与存储分离架构（共享分布式存储 + 一写多读），新增只读节点无需复制全量数据，可在秒级到分钟级完成，且存储按实际使用量计费、按量扩容。
- **易错点**：
  - ① RDS 只读实例需要从主实例复制全量数据，数据量大时创建耗时可达数小时，不满足「分钟级」；
  - ② 自建主从不仅慢，还要自行处理备份、高可用与运维；
  - ③ Redis 无法承接关系型 SQL 查询，方案选型错误。
- **延伸**：PolarDB 只读节点与主节点共享同一份存储，读到的是同一数据视图，不存在传统主从的复制延迟；但跨节点读一致性仍需关注会话级一致性配置。

## 六、云安全（第 16–18 题）

**16.** 某客户的 Web 站点部署在自建 IDC（非阿里云），近期频繁遭受 SQL 注入与 CC 攻击，希望通过阿里云 WAF 进行防护。下列做法正确的是？

- A. 只能使用透明接入，因为源站不在阿里云
- B. 必须先把源站整体迁移到阿里云 ECS 才能接入 WAF
- C. 使用 CNAME 接入，将域名解析指向 WAF 分配的 CNAME 地址，并在源站限制仅允许 WAF 回源 IP 访问
- D. 使用 DDoS 高防替代 WAF，即可同时防御应用层攻击

**答案：C**

**解析：**
- **考点**：WAF 的 CNAME 接入与源站位置无关，只需把域名解析指向 WAF 提供的 CNAME，流量即被牵引到 WAF 清洗后再回源，适用于 IDC、其他云、混合云等各种源站。
- **易错点**：
  - ① 透明接入依赖阿里云内的七层产品（SLB/ECS 等）做引流，源站在 IDC 时无法使用；
  - ② 认为接入 WAF 就自动隐藏源站 IP——若源站未限制回源 IP，攻击者扫描到源站 IP 即可直接绕过 WAF；
  - ③ DDoS 高防主要针对网络层/传输层大流量攻击，对 SQL 注入、XSS 这类应用层攻击需 WAF 的规则引擎。
- **延伸**：WAF 还支持「云产品接入」（ALB/CLB/MSE 一键接入）和「SDK 接入」（App/小程序防刷）；上线前建议先用观察模式跑一段时间，避免误拦截。

**17.** 某 ECS 的公网 IP 遭受大流量攻击，运维发现该 IP 上所有入方向流量被丢弃，SSH 也无法连接，控制台提示该 IP 处于「黑洞」状态。下列说法正确的是？

- A. 黑洞只限制攻击流量，正常用户访问不受影响
- B. 重启 ECS 实例可立即解除黑洞
- C. 升级公网带宽规格可立即解除黑洞
- D. 黑洞期间该 IP 的所有入向流量被丢弃、业务中断，通常需等待自动解除；如需快速恢复可购买 DDoS 高防清洗或更换 IP

**答案：D**

**解析：**
- **考点**：DDoS 基础防护在攻击流量超过该 IP 的黑洞阈值时，会自动将 IP 拉入黑洞——黑洞的本质是**丢弃该 IP 的全部入方向流量**，因此业务必然中断，且在黑洞期内不可自助提前解除（到期自动解封）。
- **易错点**：
  - ① 误以为黑洞是「限速」或「只清洗攻击包」，实际是「全丢」；
  - ② 认为重启实例、改配置能解除黑洞——黑洞在运营商/清洗侧生效，与实例状态无关；
  - ③ 认为加带宽能提高防护能力，实际带宽规格与清洗能力不是一回事。
- **延伸**：黑洞阈值与实例类型、公网带宽有关；业务连续性要求高的场景应提前接入 DDoS 高防（BGP 高防 IP）或使用 Anycast EIP，实现「清洗不断服」。

---

**18.** 某企业安全规范要求：RAM 用户执行删除 ECS、修改安全组等高危操作时，必须已完成 MFA 认证，且仅允许从公司出口 IP 段 `203.0.113.0/24` 发起调用。最合适的实现方式是？

- A. 在 RAM 权限策略中使用 Condition 条件（如 `acs:MFAPresent`、`acs:SourceIp`）对高危 Action 加以限制
- B. 通过 ECS 安全组限制来源 IP
- C. 为每个用户单独创建自定义策略，把 IP 段硬编码进策略的 Resource 字段
- D. 开启操作审计（ActionTrail），事后核查违规操作

**答案：A**

**解析：**
- **考点**：RAM 策略支持 Condition（条件块），可在 `Action`/`Resource` 之外追加约束，例如 `acs:MFAPresent: true` 要求已通过 MFA、`acs:SourceIp` 限定调用来源 IP，是「同一套权限、不同安全上下文」的标准实现。
- **易错点**：
  - ① 安全组控制的是网络层流量，管不住通过公网 OpenAPI 发起的调用；
  - ② 把 IP 写进 Resource 是概念错误——Resource 描述被操作的对象，IP 只能放在 Condition 里；
  - ③ ActionTrail 只做审计记录，不具备拦截能力。
- **延伸**：`acs:SourceIp` 在通过 VPC 终端节点调用时行为不同，需结合 `acs:SourceVpc`/`acs:SourceVpce` 判断；MFA 条件对使用长期 AK 的调用通常不生效（AK 调用无法证明 MFA 状态），应优先使用 STS 临时凭证。

## 七、架构设计与综合运维（第 19–20 题）

**19.** 运维团队需要统一收集 200 台 ECS 上的 Nginx 访问日志与应用错误日志，要求：秒级实时检索、按状态码与 URL 统计 PV/UV、异常关键字自动告警，并将日志长期归档到 OSS 以便合规留存。最合适的方案是？

- A. 每台 ECS 用 crontab 定时 grep 日志并汇总到一台跳板机
- B. 使用日志服务 SLS：Logtail 采集 → Logstore 建索引 → 查询分析与告警 → 投递至 OSS 归档
- C. 使用云监控自定义监控上报日志条数
- D. 将日志实时写入 RDS，再用 SQL 做统计

**答案：B**

**解析：**
- **考点**：SLS 是面向日志的一站式平台，Logtail 支持批量部署与断点续传式采集，Logstore 建立字段索引后可做类 SQL 的查询分析，配合告警规则与投递（OSS/MaxCompute）满足「实时分析 + 长期归档」。
- **易错点**：
  - ① crontab + grep 无法做到秒级检索，且在 200 台规模下维护成本极高；
  - ② 云监控面向时序指标（CPU、QPS 等），不适合承载海量日志文本；
  - ③ 日志写入 RDS 会迅速打满存储与 IOPS，成本与性能都不可接受；
  - ④ 忘记「未建索引的字段无法用于查询分析」，采集成功但查不出结果是常见坑。
- **延伸**：日志量大时应按业务拆分 Logstore 并设置合理的 Shard 数；冷数据可用「热存储 + 低频/归档存储」的分层策略降低成本。

**20.** 某公司有大量长期运行的按量付费 ECS，但实例规格会随业务季度调整，希望获得接近包年包月的折扣，同时保留随时变配、释放的灵活性。最合适的方式是？

- A. 将全部实例转为包年包月
- B. 购买地域级预留实例券（RI）抵扣按量付费实例的计算费用
- C. 将全部实例改为抢占式实例
- D. 购买 CDN 流量包与 OSS 资源包

**答案：B**

**解析：**
- **考点**：预留实例券（RI）通过「承诺使用量」换取折扣，自动匹配同地域（地域级）或同可用区（可用区级）内符合条件的按量付费实例，抵扣其 vCPU/内存的计算费用；实例仍保持按量付费的弹性，可随时变配、释放，未用完的抵扣额度还可继续匹配新实例。
- **易错点**：
  - ① 转包年包月会丧失弹性，且退订/变配受限；
  - ② 抢占式实例价格低但可能被系统回收，不适合长期稳定运行的核心业务；
  - ③ **RI 只抵扣计算资源（vCPU、内存）费用，不抵扣云盘、公网带宽、快照、流量等费用**，这是最常见的理解偏差；
  - ④ 可用区级 RI 绑定特定可用区，跨可用区部署时匹配率低，灵活性不如地域级。
- **延伸**：RI 与节省计划（Savings Plan）是两条不同路径，后者以「承诺每小时消费金额」抵扣，适合规格族频繁变化的场景；选购前应结合历史用量做覆盖率测算。

### 作答建议

1. **先做场景判断，再选产品**：ACP 题干多为「某客户遇到某现象」，第一步应识别是**计费/性能/可靠性/安全**哪一类问题，再落产品能力。
2. **警惕「绝对化」选项**：如「只能」「必须」「立即」「完全免费」，往往是错误项。
3. **注意成对概念的边界**：慢日志 vs 全量审计、版本控制 vs WORM、黑洞 vs 限速、RI vs 包年包月、CLB 七层 vs ALB，这些是最容易失分的对比点。
